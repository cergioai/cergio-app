## MEASURED defect that zeroed the old harvest
The self-stop misfires on historical rows. creator-harvest counts its CREATOR_TARGET
population as `like('discovered_via', 'se:web-harvest%')` over ALL TIME — and the table
holds ~4,211 rows under `se:web-harvest-YYYY-MM-DD` daily tags from the June/July runs
(recorded in-tree: opsPayload.ts "CREATORS TOTAL was 4,211", gate #220's "0 rows beside a
real total of 4,211"). 4,211 >= CREATOR_TARGET (100), so EVERY invocation returns
`{ paused: true, reason: 'creator target met' }` at the top of the handler — before any
search, on every cron tick, forever. The board meanwhile reports the FRESH count
(AUDIT_FRESH_SINCE = 2026-08-03) — 0/100 — which is exactly the founder's "0 progress on
creators" beside a worker that believes it already finished. Secondary (not measurable
from this container): board snapshots show `agent_runs: []`, consistent with the */15
schedule not firing live even though the FINAL migration shape is correct
(20260803030000 routes through cergio_call_edge) — so the new migration re-asserts the
cron, belt and braces. The DDG endpoints could NOT be probed from this container (proxy
403 allowlist) — v2 keeps the html endpoint and pins the lite fallback so one bot-wall
cannot zero the source.
